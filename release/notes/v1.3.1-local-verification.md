Recorded October 4, 2026 on Arch Linux x86_64 and Hyprland 0.56.2.

Frontend: 39 tests passed, TypeScript and production build passed. Rust: 61 tests passed, three opt-in environment checks excluded from the default run; formatting and clippy with warnings denied passed. Four release-gate/installer tests and the packaging script checks passed. The updated live VS Code integration check passed against empty desktop 9 and occupied desktop 1 with two distinct windows for the same folder/profile.

The 1.3.0 tagged CI and release workflows passed, and its downloaded AppImage, DEB, RPM and Apple Silicon DMG matched the draft's checksums. The AppImage started in isolated KWin 6.7.5 Wayland and in the real Hyprland session. A real profile launch to empty desktop 10 was verified, and the picker returned to the main page. A second launch of the same project reused the first VS Code window, revealing the additional bug addressed in 1.3.1. No existing user window was selected or moved to work around that failure.

The fix uses unique managed `.code-workspace` descriptors referring to the original folder. Regression tests cover distinct descriptors for the same Unicode/spaced folder, private permissions, preservation of project contents and credentials, failed-launch cleanup, and rejection of symlink escapes. The live disposable VS Code check verifies two separate workspace identities for the same profile and folder, including placement on an empty and an occupied desktop.

The complete managed data and WebKit state were backed up before the local update. 124,595 unchanged files were verified; nine logs/database files changed during active sessions. Thirty-three Codex SQLite databases were additionally captured through consistent read-only snapshots and passed `quick_check`. All six saved credentials, all six profile identifiers and all fifteen critical auth/config/metadata files were verified unchanged after the first packaged launch. Protected backup evidence and native screenshots remain local and are not committed with user data.

The existing picker fixtures/screenshots and layout checks are recorded in [the preceding verification report](v1.3.0-local-verification.md).
