# Multi Codex v1.4.1

Fix Windows account saving and PowerShell installation. The matching extension is **v0.2.1 pre-release**, with the same native credential fix.

## Windows download

**[Download Windows x64 installer (.exe)](https://github.com/wrestle-R/multi-codex/releases/download/v1.4.1/Multi.Codex_1.4.1_x64-setup.exe)**

Close Multi Codex, download the installer, and double-click it to install or update. Open Multi Codex from the Start menu afterward. Saved accounts, settings and conversations are preserved.

## Changes

- Fix “The system credential store could not save this credential” for full-sized Windows OAuth logins. Credentials remain in Windows Credential Manager, with large values stored across bounded entries. Existing saved accounts remain readable, and failed writes preserve the previous credential.
- Fix false “Windows installer checksum verification failed” errors caused by PowerShell receiving GitHub's checksum manifest as binary content. Installation and update still require one matching checksum and reject mismatched downloads before execution.
- Use basic parsing in the documented Windows download commands, avoiding Windows PowerShell's HTML script-execution prompt.
- Keep the direct Windows installer download available on GitHub and the website.

## Validation

All 15 required release gates passed across the recorded native runs: Linux/macOS/Windows builds, exact-package installer checks, account-isolation regressions, extracted VSIX tests on all four platforms, packaged Linux launcher window checks and macOS menu automation. Windows checks include full-sized synthetic OAuth credentials in the real vault, PowerShell 5.1 and 7 checksum regressions, and actual Start menu shortcut launches after install and update. The report records exact package hashes in [v1.4.1-validation.json](https://github.com/wrestle-R/multi-codex/blob/main/release/evidence/v1.4.1-validation.json). `SHA256SUMS` covers every downloadable package and install/update script.

## Compatibility and limitations

Native Windows x64 is supported. Windows credential tests use full-sized synthetic OAuth data in the real native vault; real browser sign-in, token rotation and cloud quotas require user credentials and are not exercised by CI. WSL/Remote SSH and Windows virtual-desktop placement remain deferred.

The Mac desktop app requires Apple Silicon and macOS 26; the extension also has an Intel package. Developer ID signing/notarization and the broader Linux distribution/GNOME/KDE functional matrix remain pending. Follow the website's Mac first-open instructions.

Standalone launch remains limited to verified exact builds: Linux/macOS `26.930.51102` and Windows app build `26.930.61225`.

Download the matching VSIX for Linux x64, macOS Apple Silicon, macOS Intel or Windows x64, then use **Extensions: Install from VSIX…**. Finish active work and reopen an already-open VS Code window after updating. Marketplace availability depends on the owner's manual upload and validation.
