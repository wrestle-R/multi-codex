# Multi Codex v1.4.0

Native Windows x64 support for the desktop launcher and companion extension, account actions in the macOS menu bar, all-account usage refresh, and persistent launcher maximization across desktop changes.

The matching extension is **v0.2.0 pre-release**. Download the VSIX for Linux x64, macOS Apple Silicon, macOS Intel, or Windows x64. Install it with **Extensions: Install from VSIX…**. Marketplace v0.2.0 availability depends on the owner’s manual upload and Marketplace validation.

## Windows download

**[Download Windows x64 installer (.exe)](https://github.com/wrestle-R/multi-codex/releases/download/v1.4.0/Multi.Codex_1.4.0_x64-setup.exe)**

Click the link to download the installer, double-click it, and follow setup. Then open Multi Codex from the Start menu. No PowerShell command is needed. To update, close Multi Codex and run the new installer; saved accounts and conversations are preserved.

## Changes

- Windows account storage, private ACLs, Credential Manager integration, executable discovery, isolated VS Code and interactive PowerShell/Windows Terminal launches, NSIS installer, and checksum-verified PowerShell install/update scripts.
- Windows extension includes its native executable helper and startup wrapper, uses authenticated named pipes, and shares accounts and safety locks with the desktop app.
- Account selection waits for backend readiness. Failed connections have recovery instructions, Windows executable identity handles case/path variants, and long conversation responses no longer fail at the old 8 MiB framing limit. Activity, approval, identity and rollback guards remain enforced.
- The extension toolbar checks every saved account with bounded concurrency, progress, reset times, and independent error handling. Native account rows show inline usage and switching state.
- Mac account submenus offer only installed supported launch targets and update when names or installed apps change. Closing hides the window; tray Open and Dock reopen restore it; Quit exits the launcher.
- On Hyprland, the launcher stays maximized on its original desktop through Code/standalone launches and desktop switches, and repairs a floating restore state.
- The website is the primary documentation source, with an organized GitHub wiki. README links there; release metadata lives in `release/`, and `docs/` is untracked.

## Validation

Required native CI, extracted VSIX tests, installer checks and exact-asset release gates passed. All four packages were tested in real VS Code for live attachment and isolated startup, A → B → A identity switching, chat continuation, active-work guards, error recovery and all-account usage. Native Windows runners also exercised private storage, credential integration, separate editor/CLI/standalone homes, restart guards and NSIS install/update/startup. Native Mac UI automation checked the exact DMG’s menus, close/Open/Dock reopen and Quit. The exact Linux AppImage passed both Code and standalone desktop-switch checks in the live Hyprland session.

[Validation report and exact package hashes](https://github.com/wrestle-R/multi-codex/blob/main/release/evidence/v1.4.0-validation.json). Linux/Mac desktop packages reuse the already validated build with identical platform source inputs; the report records each asset’s build commit and runner evidence. `SHA256SUMS` covers the downloadable packages and install/update scripts.

Windows native account-isolation tests use inert credentials: real OAuth/browser sign-in, token rotation and cloud quotas were not exercised. Linux and Mac authenticated standalone evidence is carried forward with current native regressions. Standalone launch is enabled only for verified exact builds: Linux/macOS `26.930.51102` and Windows app build `26.930.61225`.

Native Windows x64 is the initial scope; WSL/Remote SSH and Windows virtual-desktop placement are deferred. The Mac desktop app requires Apple Silicon/macOS 26; its extension also has an Intel package. Developer ID signing/notarization and the broader Linux distribution/GNOME/KDE functional matrix remain pending. Follow the website’s Mac first-open instructions.

To load the connection fixes in an already-open VS Code window, finish active work, install the matching VSIX and reopen that window. The update does not force a reload of ongoing work.
