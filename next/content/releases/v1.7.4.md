# Multi Codex v1.7.4

Refresh at your own pace, get an alert for the account that needs attention, and let the Orbiters dress themselves for festivals.

## Refresh

Open **Settings → Refresh** to choose 1, 5, 10, 15, 30 or 60 minutes. The default is **10 minutes**. This controls usage and app-update checks, including while the launcher is in the tray. **Refresh all** still checks immediately. Local session status stays on its own responsive schedule.

Faster checks use more network and battery and can hit service rate limits. Alerts arrive after the next successful check; sleep, connectivity and service delays can delay them.

## Account notifications

The notification inbox keeps the latest 100 alerts on this device. **Settings → Notifications** controls each account and alert type:

- A new banked reset added to an account, saved for later use.
- Weekly usage restored, including an early reset. This reports the observed allowance change, without guessing which promotion caused it.
- Remaining usage crossing your selected 20%, 30% or 40% levels.
- An expired account sign-in, with a reminder to open **Edit → Sign in again**.
- A new Multi Codex version on your selected update channel.

Existing banked resets form a baseline on first use. Repeated checks do not repeat the same grant or sign-in expiry alert. Low-usage alerts rearm when usage recovers. The existing expiring-reset reminder also has its own switch.

Desktop notifications are optional. Enable them in notification settings, allow the system permission, and use **Send test notification**. Focus or Do Not Disturb can hide them. Account alerts need Multi Codex to remain running; quitting the app stops checks.

## Six characters, automatic festival clothing

The six colours now each have one consistent character and accessories. New accounts receive a colour from the least-used group, while saved assignments stay stable. Existing accounts move once to this six-template set; account IDs, credentials and conversations are unchanged.

Festival outfits turn on automatically using the device's local date, with researched dates for the remainder of 2026 and all of 2027–2029. Themes cover Halloween, Christmas, Diwali, Easter, Holi, both Eids, Lunar New Year, Onam, Pongal, Navratri, New Year and Valentine's Day. Dates use India reference observances; regional and moon-sighting dates can differ.

Use **Settings → Orbit → Festival clothing** to turn automatic outfits off. There is no festival selector or calendar page. All Orbit controls, including Enable Orbit, now live inside Orbit rather than Launch settings. Idle avatars stay still.

## Updating and compatibility

Use the launcher's **Update** button to install this stable release. Saved accounts and chat history remain in place. Platform requirements stay the same: Apple Silicon macOS 26+, supported Linux packages and Windows x64. Orbit remains available on macOS and supported Linux Wayland desktops; Windows Orbit is not supported. Mac packages are ad-hoc signed without Developer ID/notarization, and macOS 27 remains unverified.

## Validation

The [native release workflow](https://github.com/wrestle-R/multi-codex/actions/runs/39935371862) passed for Linux, macOS, Windows and all four extension targets. It checks native builds, synthetic account isolation, packaged startup, installers and signed-updater acceptance/refusal. Linux and Mac checks also cover duplicate launches; Mac checks cover Orbit and tray close/reopen behavior. Exact package hashes and test scope are recorded in the [release evidence](https://github.com/wrestle-R/multi-codex/blob/main/release/evidence/v1.7.4-validation.json). Real-account promotional delivery and system notification banners under every OS privacy/Focus configuration are not claimed as tested.
