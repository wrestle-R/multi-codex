# Multi Codex v1.5.0

This release adds detailed profile storage controls, local conversation cleanup and a signed in-app updater.

## Storage and local conversations

Open the storage total in the header, then expand **Data and chats** under an account. The breakdown shows Codex data, VS Code data, installed extensions, Codex Desktop data and the chat transcript subset. Cache and chats are included in total storage; they are not additional storage totals.

Two separate actions let you clear **all saved local chats** or **chats last active more than 30 days ago**. The preview shows the selected count and transcript size before confirmation. Recently continued conversations are kept by the 30-day action; older parents are kept when deleting them could remove newer subagent conversations.

Cleanup uses Codex's native thread deletion and removes the selected local prompt-history and title-index entries. Credentials, settings, skills, plugins, extensions and project files are preserved. A busy account must be closed before cleanup. Changes since the preview, uncertain activity or unsafe paths stop the operation and require a fresh preview.

Deletion is permanent. These controls delete local conversations, including archived conversations; they do not delete cloud conversations or promise cloud restoration. A failure after some native deletions reports partial progress. There is no automatic retention policy or fixed storage cap.

## One-click updates

The **Update** button checks the latest stable release, downloads its matching signed package, shows progress, installs it and displays the restart state. Errors offer a retry. Saved accounts and profile data are preserved; separately launched Codex sessions remain separate.

In-app updates support Linux x64 AppImage, Apple Silicon macOS app bundles and Windows x64 installers. Linux `.deb` and `.rpm` users continue to update through their package manager. The updater verifies the release payload signature; that signature is separate from Apple Developer ID signing and notarization.

## Upgrade and compatibility

- Existing v1.4.1 installations need the website's [update command](/docs#updates) or the new platform installer once, because those older packages do not contain the Update button. Later signed releases can be installed from the button.
- The Mac launcher requires Apple Silicon and macOS 26 or newer. The Windows launcher supports x64. The Linux launcher supports x64; the separate CLI plan discusses ARM64 support but does not add an ARM64 launcher package in this release.
- Apple Developer ID signing and notarization are not configured. Use the website's documented unsigned Mac installation process; updater signatures do not remove macOS first-open requirements.
- Local chat cleanup requires an installed compatible Codex engine that supports native thread deletion. An unavailable or unsupported engine produces an explanation instead of deleting files directly.
- Codex Desktop account launch compatibility remains limited to the versions already validated by the launcher. This release does not expand that allowlist.
- The moving Windows Codex download currently provides an unverified build. The launcher refuses it without launching or changing the saved login. Native launch/restart evidence for the supported older Windows build is carried forward; this release's Windows checks exercise fresh VS Code/CLI isolation and the unsupported Desktop refusal.

## Documentation and scope

Full release details now live on this website. GitHub provides downloads and a short link to the corresponding release page. See the [storage and updates guide](/docs/storage-and-updates) for file locations, cleanup behavior and updater requirements.

`plan-cli.md` specifies one complete Mac/Linux CLI with full launcher feature coverage and new-terminal account launches. It is a planning document; this release does not implement that separate CLI. The shared VS Code storage and cross-account conversation proposals remain separate planning work.

## Validation

Publication requires native Linux, Mac and Windows package checks, exact-package installer checks, extension checks, launcher-window and Mac menu checks, matching artifact checksums and signed updater manifests. The final evidence is recorded in [the v1.5.0 validation report](https://github.com/wrestle-R/multi-codex/blob/main/release/evidence/v1.5.0-validation.json).

Broader Linux distribution/GNOME/KDE coverage, Apple notarization and real Windows cloud OAuth validation are outside those checks. Local conversation cleanup was also exercised against disposable conversations using the installed official Codex engine; no real user chats were deleted during development.

The native updater SDK downloaded, verified and installed the exact Linux AppImage in a disposable test, and rejected an altered payload before replacement. All three update payload signatures were checked. Mac/Windows installer and restart checks passed; their updater SDK installation paths and updater-triggered restart were not directly exercised.
