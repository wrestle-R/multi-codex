# Multi Codex v1.5.3

The Linux AppImage now supplies its bundled library paths to WebKit's child helper programs. A compatible Linux system no longer needs a separate WebKit installation for those helpers to start.

This completes the helper-loading fix begun in v1.5.2. That release corrected where the helper executables were found; the catalog retry then exposed a separate library-search problem that the native build runner's installed WebKit had masked. v1.5.3 keeps the helper working-directory fix and adds the inherited bundled-library directories.

Release validation now removes system WebKit and JavaScriptCore after building, verifies their absence, and tests the actual AppImage in an offline Firejail sandbox. A compiled child-process regression also verifies loading a dependency that exists only inside the package.

Mac install and update scripts continue to use `/Applications/Multi Codex.app`. Saved accounts, credentials, conversations and settings retain their current data locations. Quiet update discovery, signed packages, progress and restart behavior remain available.

## Validation

The exact tagged Linux package passed catalog-style launch and nonblank screenshot checks with system WebKit removed. Cold and repeated sandbox starts and direct launch passed. Native Linux and Apple Silicon Mac packages, install/update checks, Mac account menus and all four packaged extension targets passed. A fresh Windows run of the same source passed native credential, editor, extension, signed installer and restart checks after an initial credential-deletion assertion failed; the initial aggregate is recorded as failed.

All 19 published assets match the tested hashes. Linux, Mac and Windows updater signatures verify against the configured public key, and altered payloads are rejected. Both Mac installer scripts retain the system Applications destination and passed native DMG replacement, signature, startup/restart and account/chat-preservation checks in disposable fixtures.

The [public AppImageHub retry](https://github.com/AppImage/appimage.github.io/actions/runs/38356689924) passed on the published v1.5.3 AppImage and produced its main-window screenshot. The catalog PR's origin check passed as well.

Direct Mac/Windows in-app updater installation was not rerun for this packaging fix. Apple notarization and the wider Linux distribution/desktop matrix remain outside the completed checks.
