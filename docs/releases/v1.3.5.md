# Multi Codex v1.3.5 — candidate

Open an account in VS Code or the standalone Codex app using the same isolated Codex home. When both apps are installed, Launch settings offers VS Code only, Codex app only, or Both. Both shows two launch buttons; a single installed app is selected automatically without showing the choice section. Existing users retain VS Code as their initial preference.

Two different disposable identities passed native desktop credential reuse, refresh, logout and restart isolation on Linux and a Mac GitHub runner. Standalone support is limited to the tested desktop version `26.930.51102` on Linux x86_64 and Apple Silicon macOS 26. Unknown desktop versions stay disabled until verified. See [authentication evidence](v1.3.5-auth-isolation.json).

Each profile keeps its existing credentials and Codex home; desktop cookies and app state live in a separate `desktop-data` directory. Mac launches use private short path aliases for socket compatibility. The normal browser HOME is preserved. Cleanup and account edits are blocked while either app uses that profile. A deliberate desktop logout cannot silently restore old keyring credentials during a usage check; sign in again from Edit.

Preferred folder + Browse uses the existing folder picker. Advanced paths stay collapsed. The desktop toggle remains Linux-only, and Mac launches do not open that picker. Standalone relaunch reuses its own account window; VS Code relaunch continues opening a new window.

Local validation: 59 frontend and 70 Rust tests, production frontend build, formatting, packaging, installer and secret checks. CI additionally exercises the actual Mac standalone launch twice, including a visible native window, long paths with spaces/Unicode, bundled CLI discovery, running-profile guards and unchanged credential fixtures.

This remains a draft candidate pending the broader distribution/signing validation manifest. Apple signing/notarization and untested platform checks are not claimed complete.
