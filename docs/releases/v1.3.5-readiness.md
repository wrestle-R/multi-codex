## Publication procedure

1. Finish the pending installed-package/signing checks and record exact OS/version, tester, timestamp, evidence and matching artifact SHA-256 in the manifest.
2. Require `npm run check:release-gates -- /absolute/path/to/assets` to pass. Until then, keep the release a **draft candidate** and describe the verified scope accurately.
3. Publish only the exact validated assets. Preserve profile directories and credentials during upgrades; keep the local backup available for rollback.

The normal [update script](../../scripts/update-app.sh) follows the latest **public stable** release, currently v1.2.3. It must not be used to install this draft, because that would select the older public release. The local v1.3.5 installation was updated from the verified candidate directly. Neither the completed build nor the local checks establish a flaw-free result across all operating systems.
