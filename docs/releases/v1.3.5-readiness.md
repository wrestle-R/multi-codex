## Candidate completion steps

1. Finish and commit the window fix and this checklist, then require final CI green on the exact commit. Update [candidate notes](v1.3.5.md) and README version text if release status changes.
2. Create `v1.3.5` only from that tested commit. Wait for all release jobs and draft assets, and verify each artifact against `SHA256SUMS`.
3. Test the downloaded AppImage with a separate disposable Multi Codex data root before touching the installed app. Test both launch buttons and same-account mixed use against the release binary.
4. Back up the current full app data, six profile IDs and credential files, installed executable, desktop entry, and default Codex auth/config. Verify the backup. Replace only the launcher, then check the same six IDs and live credentials remain; keep the backup for rollback.
5. Publish a stable release only after the remaining validation gates pass. Until then, label any built release **draft candidate** and do not describe Mac or Linux package support as fully validated.

The normal [update script](../../scripts/update-app.sh) follows the latest **public stable** release (currently v1.2.3), so it must not be used to install this draft. The existing [v1.3.5 candidate notes](v1.3.5.md) describe the planned features. This checklist records the outstanding validation work; a completed draft build is separate from stable publication.
